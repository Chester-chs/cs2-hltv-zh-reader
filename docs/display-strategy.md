# Display Strategy Proposal

Status: proposal for Gate 4 owner review. This document does not authorize display implementation. The `/matches` parent-selector check is complete: no target-parent positional selector was found, while fixed dimensions make `match-stage` and `match-meta` Mode A only. CSS for match-detail and news target parents remains `Unable to confirm`.

## Rules applied to every row

- The original string remains authoritative in the in-memory record table; the DOM is not the source of truth.
- If translation equals the original, or the value is pure numeric, pure date, or pure symbol text, write nothing. Mode A does not replace it and Mode B does not insert anything.
- IDs, URLs, attributes, data values, canonical team/player names, scores, and live values are protected unless an owner-approved glossary later says otherwise.
- For `/matches`, use the element-level CSS boundary below: `match-teamname`, `match-event`, and `match-time` are bilingual-feasible candidates; fixed-dimension `match-stage` and `match-meta` are Mode A only. Do not transfer this result to match-detail or news containers whose parent CSS has not been checked.
- `data-countdown-target-timestamp` content is currently prohibited from translation because HLTV overwrites its child text every second.

## Current approval boundary

The local `/matches` CSS evidence supports this element-level boundary:

- Bilingual feasible, with no fixed width on the target rules found in this scan: `match-teamname`, `match-event`, and `match-time`. Evidence: `raw-capture/gate3/matches-style.css` (2,524,977 local bytes), `.text-ellipsis`, `.matches-v4 .match-team`, `.matches-v4 .match-teamname`, `.matches-v4 .match-event`, and `.matches-v4 .match-time`; the scanned positional selectors are on `.match-time-wrapper`, not the target parents.
- Mode A only because of fixed dimensions that can clip or overflow inserted content: `match-stage` and `match-meta`. Evidence: the same stylesheet's `.matches-v4 .match-stage` 14px height/line-height and 62px/51px/45px/65px variant widths, plus `.matches-v4 .match-meta` 28px/22px widths.
- Translation forbidden: elements carrying `data-countdown-target-timestamp` and `data-livescore-*`. Evidence: `hltv-matches-js.js` rewrites countdown child text every second, and the Socket.IO livescore module writes live values through `textContent`; these dynamic-writer facts take precedence over static layout.

This boundary covers `/matches` only. Parent CSS for match-detail `.match-page`/score areas and news `newsline`/`newstext` has not been checked and remains `Unable to confirm`; those routes are not approved by the `/matches` evidence. Gate 4 must still approve each row before any DOM replacement, sibling insertion, observer reconciliation, translation request, or glossary implementation begins.
