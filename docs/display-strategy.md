# Display Strategy Proposal

Status: Gate 4 owner-confirmed strategy. The working tree implements evidence-backed selectors for `/matches`, shared navigation/sidebar/footer chrome, captured news and article content, comments, selected match-detail headings and controls, two `/events` headings, the `/ranking/teams` regional-ranking control, route-limited headings on `/results` and `/players/archive`, headings on the exact `/fantasy` overview route, and two controls on the exact `/live` route. The screenshot follow-up additionally covers the top-bar sign-in text, player-of-the-week labels, minigame heading/action, and two static left-sidebar CTAs; the ranking update label/date and player statistics remain untouched. Results filter class selectors are enabled only on `/results` as narrow candidates; their binding to visible filter labels remains `Unable to confirm`. Fantasy heading and Live control selectors are based on normal Chrome accessibility roles and have not been verified against raw markup or an installed extension. The `/major` and general `/forums` page bodies remain uncovered. The Terms of Service body is intentionally left untouched; only its shared site chrome is eligible. Coverage is not established for every HLTV route. The exact DOM binding for the event-heading classes and several other route templates remain `Unable to confirm`. Fixed dimensions still make `match-stage`, `match-meta`, and `newstc` unsuitable for insertion. The full CSS for the match-detail `.match-page`/score area remains `Unable to confirm` and is outside this implementation.

## Rules applied to every row

- The original string remains authoritative in the in-memory record table; the DOM is not the source of truth.
- If translation equals the original, or the value is pure numeric, pure date, or pure symbol text, write nothing. Mode A does not replace it and Mode B does not insert anything.
- IDs, URLs, attributes, data values, canonical team/player names, scores, and live values are protected unless an owner-approved glossary later says otherwise.
- For `/matches` and the inspected news/article containers, use the element-level CSS boundary below: `match-event`, archive `newstext`, and article prose are eligible in Modes A and B; `match-teamname` and tooltip-linked article entities are never translated; fixed-dimension `match-stage`, `match-meta`, and `newstc` are not insertion targets. Do not transfer these results to the uninspected match-detail `.match-page`/score area.
- `data-countdown-target-timestamp` content is currently prohibited from translation because HLTV overwrites its child text every second.
- Global time-field rule: any element carrying both `data-time-format` and `data-unix` is prohibited from translation and sibling insertion. Confirmed evidence covers match-list `.match-time`, comment `span.time`, article `div.date`, and match-detail time fields.

## Gate 4 implementation agreements

- Provider boundary: use an interchangeable LLM provider interface around the OpenAI-compatible `/chat/completions` protocol. DeepSeek, OpenAI, and a local model must be selectable by changing only `baseURL` and model name; no provider is selected or hard-coded at this gate, and DeepL is not used.
- Partial event translation: `glossary.json` entries with `keep_as_is` define the protected brand fragments. The prompt must list those fragments as immutable for each request. The response must be validated for byte-for-byte retention of every protected fragment; on failure, discard the result, render nothing, and fall back to the original. Reordering such as `Fall 2026` → `2026 秋季赛` requires structural validation and may not rely on unconstrained model output alone.
- Comment translation: translate a comment only when it is classified as English. A low-confidence result, a failed classification, or a comment containing Chinese characters keeps the entire original comment. Comments are translated as a whole and never use the partial-translation path. Failed or uncertain comment classifications must be recordable for later review.
- P0-LANG: when language confidence is low, preserve the original rather than making a destructive translation decision.

## Glossary asset contract

The repository-root `glossary.json` is the authoring asset with this schema:

```json
{
  "version": 1,
  "entries": [
    {
      "term": "StarLadder StarSeries",
      "target": "StarLadder StarSeries",
      "keep_as_is": true,
      "category": "event",
      "note": "品牌名，保留英文"
    }
  ]
}
```

Every entry must provide `term`, `target`, `keep_as_is`, and `category`. A loader must reject an entry and report a diagnostic when `keep_as_is` is `true` but `target` differs from `term`; it must not silently normalize the contradiction. The `version` field reserves room for future schema evolution.

Vite copies the root asset to `dist/glossary.json` for the background loader and embeds that same authoring asset in the content IIFE for immediate fixed-label rendering. Installed runtime code uses these built resources, never the repository path. The root glossary remains the sole terminology authority.

## Current approval boundary

The Gate 4 decisions and evidence boundaries are:

- Never translate team names: `match-teamname` is Mode A no-op and excluded from Mode B by owner decision.
- Partially translate event names on `/matches`: `match-event` is structurally bilingual-feasible because the target rule is flex-based with no fixed width/height rule found. Evidence: `raw-capture/gate3/matches-style.css` (2,524,977 local bytes), `.matches-v4 .match-event`. Protected brand fragments follow the partial-translation contract above.
- `match-time` is treated as `never` in B1. Although no fixed width rule was found, match-time is a dynamic/pure value and is covered by the global `data-time-format` + `data-unix` prohibition. Encoding the whole element as no-op is behaviorally equivalent to checking the attributes one by one and is less likely to miss a dynamic value. Evidence: the same stylesheet's `.matches-v4 .match-time` plus the global time-field evidence.
- Mode A only because of fixed dimensions that can clip or overflow inserted content: `match-stage` and `match-meta`. Evidence: the same stylesheet's `.matches-v4 .match-stage` 14px height/line-height and 62px/51px/45px/65px variant widths, plus `.matches-v4 .match-meta` 28px/22px widths.
- Comments now support Modes A and B for confidently English full-comment bodies, following the user's complete-Chinese request. Evidence: the supplied stylesheet's `.forum .forum-middle` rules have no fixed width/height or `overflow:hidden`; `content-visibility:auto` remains a recorded scroll-layout risk.
- Home news section headings, news titles, and article bodies use Modes A and B with the inspected `.index .newsheader`, `.index .newstext`, and `.newsdsl .newstext-con`/`.news-block` CSS evidence. The home selector targets `h2.newsheader` only; tooltip-linked article entities remain unchanged. The conclusion is scoped to those structures; no news result is transferred to the uninspected match-detail `.match-page`/score area.
- Five match-detail section headings use Mode A replacement through selectors limited to betting, lineups, past matches, head-to-head, and VRS forecast headings. The live score/map area remains unimplemented and unconfirmed.
- Primary global navigation labels use Mode A through `.navbar .navcon a.nav-link`; this excludes the separate smartphone quick-navigation bar. Version 0.0.6 adds a separate fixed-label dropdown strategy; see below. The local captures and shared stylesheet support the selector and mobile clipping rationale; rendered-browser behavior remains unverified.
- Captured static sidebar headings, match-list headings and filters, the article title, and three match-detail map-stat tab labels use Mode A replacement. The player-of-the-week category/metric labels, minigame heading/action, and static ranking/event calendar CTAs also use replacement; player identity/stat values, ranking update metadata, tournament names, region counts, and the CSS-generated NEW badge remain excluded.
- Results and player-archive H1 candidates are route-limited; only the observed results/player-directory page headings qualify. The exact `/fantasy` overview gets heading candidates only. On `/live`, only the Fullscreen and Theater control candidates are enabled. Leaderboard/user data, match/team names, scores, and streams remain untouched; `/major` and the general `/forums` body do not yet have page-specific selectors.
- Shared footer headings, promotional copy, CTA, text links, and responsible-gaming warning use Mode A replacement across the five captured page templates. Link destinations and neighboring logo elements are preserved; narrow-screen rendered fit has not been browser-verified.
- The initial sequential `curl.exe` requests to `/events`, `/results`, and `/ranking/teams` returned HTTP 403 with `Cf-Mitigated: challenge`. Later Chrome views confirmed visible content on those routes, `/players/archive/active`, `/fantasy`, `/live`, `/major`, and `/forums`. The event-page heading class binding, results-filter class binding, Fantasy/Live DOM selector bindings, and unimplemented route templates remain `Unable to confirm`; the narrow selectors do not establish full route coverage.
- Normal Chrome accessibility views of `/player/8528/hobbit` and `/team/12467/parivision` confirmed profile tabs and static section wording, but did not establish DOM selector bindings. Player/team profile bodies have no page-specific selectors. Dynamic names, statistics, rankings, and FAQ text containing team/player identities remain protected. - News metadata `.newstc` is prohibited from translation and insertion because of `min-width:80px` and right alignment.
- The global `data-time-format` + `data-unix` prohibition covers match-list, comment, article, and match-detail time fields.

Evidence: `hltv-matches-js.js` rewrites countdown child text every second, and the Socket.IO livescore module writes live values through `textContent`; these dynamic-writer facts take precedence over static layout.

## 0.0.3 text admission and fixed chrome

This section supersedes the earlier uncovered-body/NEW-placeholder notes. A centralized `body` strategy admits complete known UI wording without guessing template classes. The statistics and profile routes select their scoped glossary categories; generic shared labels use `ui`. Unknown short strings receive no intent. Known public routes also admit prose with at least four Latin words and the prose classifier. This fallback is replacement-only and preserves nested candidates, live writers, executable/editable content, and forum/activity containers. Activity title spans and the captured comment template use their explicit strategies.

Known input placeholders are a narrowly approved attribute exception. They are registered in the in-memory display record table and restored from it, and entered values are never inspected. The CSS-generated minigame badge gets a removable glossary-derived style overlay. Both revert in disabled/bilingual mode. All terminology still comes from `glossary.json`; real installed rendering and exhaustive route coverage remain **Unable to confirm**.
